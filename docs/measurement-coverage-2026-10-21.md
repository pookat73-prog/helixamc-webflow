# 전 페이지 측정 보완 — 2026-10-21

사용자 지시: 소개 페이지 일산·특화진료 버튼의 과거 측정 제외를 해제하고, 조사에서 발견한 측정 문제를 전부 개선한다. 화면·의료 콘텐츠·상담 저장 위치는 변경하지 않는다.

## 코드 변경

- 소개의 일산/특화진료 CTA: `about_ilsan_cta_<device>` / `about_specialty_cta_<device>` 추가.
- 공통 `ui_click`: 링크·버튼·필터·탭·카드의 클릭을 캡처한다. 상세 이벤트와 같은 `interaction_id`로 연결하며 `conv=0`이다. 클릭 총수는 **ui_click만** 센다. 상세 이벤트와 합산하지 않는다. 입력한 이름/전화/증상/클립보드 내용은 읽지 않고 URL 쿼리도 제거한다.
- `session.js`: 현재 페이지·기기·발생 시각·고유 이벤트 값·측정 버전을 모든 이벤트에 보완. 페이지명이 틀리거나 비어 있던 의료진/분과/서브헤더/SVICC도 현재 경로로 정규화한다.
- `content_type`/`content_id`: 표준 내용 분류/식별자에도 공개 의료진·진료항목·증상·인증·CTA 출처를 넣는다. 원래 세부 파라미터도 유지한다.
- 상담: 시작·필드 시작/변경 여부·개인정보 설명 펼침/접힘·제출 시도·입력 오류·저장 실패·닫기/중도 포기를 추가한다. 개인정보 원문을 측정에 넣지 않는다. 성공은 Firebase가 저장 키를 반환한 뒤에만 발생한다. 비동기 저장 도중 창을 다시 열어도 원래 신청 출처를 보존한다.
- `cta_form_open`만 상담 진입 전환이다. 과거 `cta_open`은 기록을 유지하되 `legacy_event=1, conv=0`으로 중복 전환을 막는다.
- 광고: 기존 Meta/TikTok 픽셀 ID를 유지하고, 저장 성공 후에만 `Lead`/`SubmitForm`을 호출한다. 저장 키를 중복 방지용 식별자로 사용하며 폼 값은 전달하지 않는다. 플랫폼 자동 규칙과 실제 수신·광고 집계는 별도 확인이 필요하다.
- FAQ: 탭·필터·페이지 이동 시 이전 질문 읽기를 종료한다. 선택 해제·질문 닫기 기록을 추가했다. 질문·의료진·인증·응급증상의 읽기는 숨은 탭 시간을 제외하고, 60초 무조작을 넘겨 세지 않는다.
- 의료진: 프로필별 읽기·닫기 추가. 인증: 장 이동·장별 읽기·닫기 추가. 인증 iframe은 기존처럼 `sandbox="allow-same-origin"`으로 스크립트 실행을 막고, 바깥 페이지가 계측한다. iframe 자체 페이지뷰를 새로 만들지 않는다.
- 시설 갤러리: 기존 화살표 외에 점·실제 장이 바뀐 스와이프·키보드 이동을 추가했다. TOP 클릭과 공지 팝업 노출/닫기도 계측한다. 공지 팝업의 기존 비활성 설정은 유지한다.
- 전송: sendBeacon 거부/예외 시 fetch로 전환한다. IP 확인 대기는 1.5초로 제한한다. **전송하지 못한 오프라인 이벤트만** 세션 저장소에 최대50건/10분 보관하고 온라인 복귀 시 한 번 전송한다. 이미 브라우저가 수락한 요청은 수신 확인 없이 반복하지 않는다.
- GA4 한 이벤트의 25개 파라미터 한도에 맞춰 상세 행동·식별 정보를 우선한다. 원본 시트에는 전체 정보를 유지한다. 수신 웹앱/주소는 변경하지 않는다.

## 전역 진입점 게시 — 코드 반영과 별개

`measurement-site-head.template.html`과 `measurement-site-footer.template.html`의 `__MEASUREMENT_COMMIT__`을 검증된 실제 커밋으로 치환하여 API로 적용한다. 사용자에게 붙여넣기를 요구하지 않는다.

1. 사이트 head에서 무조건 실행되던 GA4/Meta/TikTok 코드를 제거한다. 기존 GSAP·사이트 인증 메타값은 보존한다.
2. 첫 외부 진입점으로 `global/measure-gate.js`를 불러 제외 여부를 먼저 정한다. 사이트맵의 모든 최상위 페이지에 공통 측정 모듈을 연결한다.
3. 이 진입점은 최신 SHA를 조회하되, 조회 실패/2.5초 지연 시 **같은 검증된 게시 SHA**로 복구한다. 파일 로드 실패 때도 게시 SHA로 한 번 복구한다.
4. 스테이징·운영자·iframe은 기존 gtag가 있더라도 차단한다. GA4 비활성 플래그를 함께 설정한다. 옛 상담 코드가 GA를 거치지 않고 쓰던 전화 클릭 전용 DB 요청도 제외하되 실제 상담 접수는 보존한다.
5. 인증 상세 등 독립 페이지의 상담은 공통 측정 준비 후 한 버전만 불러온다. 옛 고정 상담 코드가 먼저 실행돼 최신 측정을 막던 경로를 제거한다.

**주의:** 새 사이트 head/footer는 Webflow Publish 전에는 운영에 반영되지 않는다. 저장소 main 변경만으로 이미 게시된 head의 선행 페이지뷰·광고픽셀을 소급 차단할 수 없다.

이번 조사 시점 Webflow에는 정식 도메인의 마지막 게시 이후 생성된 의료진 상세26개와 서초 페이지 변경이 있다. 전체 Publish는 이 변경도 함께 공개한다. 도구에는 사용자 콘텐츠를 보존한 코드 전용 게시가 없으므로, 해당 미게시 변경을 함께 공개할 권한이 확인되기 전 전체 Publish를 실행하지 않는다. 원본 전역 코드와 치환 후 코드는 작업 증거 폴더에 보관한다.

## GA4 관리자 설정

연결된 Windsor GA4에는 쓰기 액션이 없다(`list_actions` 결과 빈 배열). Windsor의 계산 필드는 GA4 맞춤 정의 등록과 다른 기능이므로 대신 만들지 않는다.

등록할 정의는 `measurement-ga4-definitions.json`에 정리했다. 기존 속성 항목과 이름·범위를 대조한 뒤 없는 것만 등록해야 한다. GA4 관리자 설정은 권한 있는 도구 또는 사용자 브라우저 연결이 확보된 후 적용한다. 등록 이전 데이터가 자동으로 소급 복구된다고 설명하지 않는다.

고유 이벤트/방문/폼/클릭 식별자는 값 종류가 너무 많으므로 맞춤 측정기준으로 등록하지 않는다. 원본 로그의 연결·중복 검수에 사용한다. 누적 시간과 증가분도 합산 규칙을 구별한다.

## 검증

- 새 공통 측정 회귀 검사: `node scripts/test-measurement-coverage.mjs` (13개).
- 기존 상담4/상단 지점바8/섹션12/외과CTA4/일산 진료소식4 검사도 유지한다. 사이트 품질 검사와 새 측정 검사를 GitHub Actions에 연결했다.
- 실제 운영 HTML에 로컬 수정 자산과 준비된 전역 코드를 적용한 브라우저 시험: 12페이지×2기기 + 스테이징/운영자 제외4조건. 모든 POST와 분석 호스트는 차단하며 Firebase 성공/실패만 모의 응답한다. 원본 시트 저장 시도와 GA 이벤트가 대응하는지 확인한다.
- 인증 iframe은 내부 스크립트가 금지된 기존 구조이므로 제외 플래그 실행을 요구하지 않고, iframe의 이벤트0·sandbox 유지·부모 이벤트를 검증한다.
- GSAP3.12.2·jQuery3.5.1은 검사 환경에서 허용된 동일 버전 CDN으로 제공한다. 폰트 호스트 차단으로 생긴 WebFont 오류는 사이트 결함으로 판정하지 않는다.
- 최종 운영 확인은 main 실제 자산 SHA와 Webflow 게시 HTML을 따로 확인한다. 외부 분석 SDK/수집 호스트가 이 환경에서 차단되므로, 모의 전송 성공을 GA4·광고 플랫폼·Apps Script 저장 완료로 간주하지 않는다.

## 남는 경계

브라우저가 종료되거나 네트워크가 끊긴 경우 100% 저장을 보장할 수 없다. 수신 웹앱의 확인 응답·서버 중복 제거는 현재 소스/쓰기 도구가 없어 구현하지 않았다. 수신 웹앱을 임의로 재배포하지 않는다.

전화 클릭은 통화 완료가 아니고 지도 클릭은 내원이 아니다. 실통화·실내원 성과는 전화/접수 시스템 연결이 있어야 측정할 수 있으며 가짜 성공 이벤트를 만들지 않는다.
