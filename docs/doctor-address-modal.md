# 의료진 모달 자체의 고유 주소 — 스테이징 우선 반영

사용자가 별도 이력 페이지로 이동하는 단계를 원하지 않는다고 명확히 요청했다. 아래 방식이 최신 요구사항이며 이전의 ‘전체 이력 페이지 보기’ 방식에 우선한다.

- 사용자 검토는 스테이징에서 진행한다. 로컬 검토를 선행 조건으로 요구하지 않는다.
- 스테이징: `https://helixanimalmedicalcenter.webflow.io/seocho?fresh=1#vets`, 직접 접속: `/doctors/isoyun`.
- 운영 게시와 Search Console 제출은 각각 별도 명시적 승인이 필요하다.
- CMS/새 라이브러리 없음. 개인 JSON은 변경하지 않음.

## 동작

1. 기존 카드 클릭은 기존 모달을 연다. 현재 문서를 다시 불러오지 않고 History API로 `/doctors/<slug>` 주소와 제목·대표 주소를 함께 갱신한다.
2. ‘전체 이력 페이지 보기’ 버튼은 제거한다. 주소 표시줄의 주소를 바로 공유한다.
3. 닫기/ESC/배경 클릭/브라우저 뒤로 가기는 이전 주소·제목·대표 주소·카드 포커스·스크롤 위치를 복원한다. 앞으로 가기는 같은 모달을 다시 열며 새 클릭 이벤트를 만들지 않는다.
4. 공유 주소 직접 접속·새 탭·새로고침에서도 같은 모달 모양을 보여준다. 해당 의료진 본문은 최초 HTML에 포함된다. 별도 소개 페이지·이동 버튼·추가 탐색 단계가 없다.
5. 직접 접속한 모달의 닫기/ESC/배경 링크는 서초 의료진 안내로 이동한다. 외부 검색에서 들어온 브라우저의 뒤로 가기 기록을 임의로 바꾸지는 않는다.
6. 카드의 분과·순서·디자인과 방사선사 카드의 버튼 숨김은 그대로 둔다. 검색 가능한 이름 목록의 링크도 같은 모달을 열도록 생성한다.

## 측정

- 기존 `seocho_doctor_detail_desktop/mobile` 이벤트는 클릭당 1회 유지하고 `view_type=modal`, `page=seocho`, 클릭 당시 원래 `page_location`을 명시한다.
- URL 변경과 뒤로/앞으로 이동에는 새 클릭 이벤트나 `doctor_page_view`를 추가하지 않는다.
- `doctor_full_history_click`은 이동 버튼과 함께 제거한다.
- 실제 문서가 직접 로드된 방문은 기존 공통 모듈의 `doctor_page_view`로 별도 집계한다. 이 값과 모달 선택 수를 더하지 않는다.
- GA4 향상 측정이 History 변경을 자동 page_view로 수집할 수 있으므로, `/doctors/` 경로의 기본 page_view만으로 직접 방문 수를 단정하지 않는다. 실제 GA4 설정/수신은 운영 승인 후 검증해야 한다. 공용 분석 head는 변경하지 않는다.

## 검증 및 이후 반영

1440px/390px 모두 26명 JS 비활성 본문·고유 제목·대표 주소·HTTP/404 검사를 통과했다. 24명 기존 카드에서 원본 이력과 URL 변경·문서 유지·포커스/스크롤 복원·뒤로/앞으로·새 탭·새로고침을 검사했고 모듈 이벤트 중복이 없었다. 실제 분석 서버 전송은 차단한 로컬 검사다.

사용자 지시에 따라 스테이징에 먼저 적용할 때에는 같은 커밋으로 카드/모달 자산과 26명 원문 HTML/head를 함께 갱신한다. 직접 접속 화면에도 `modal.js`가 필요하다. 기존 페이지 ID는 `doctor-staging-deployment.json`을 재사용하고 페이지를 중복 생성하지 않는다. 의료진 링크 목록에도 새 모달 속성을 반영한다. 스테이징 noindex와 운영 게시/검색 제출의 별도 승인 조건은 유지한다.
