# HELIX 홈페이지 안정화 — 코덱스 개발 수칙

작성일: 2026-11-13 (Asia/Seoul). 상태: **개발 수칙 설계안, AGENTS.md 통합 전**.
대상: 이 저장소의 후속 코드·스타일·로더·검증 작업. 목표 구조와 구현 단위는 [02-architecture.md](02-architecture.md)에 있다.

## 1. 적용과 자율 진행

사용자의 최신 요청, 적용되는 AGENTS.md, CLAUDE.md의 관련 보호·배포 규칙을 먼저 대조한다. 이 문서는 기존 지침을 몰래 교체하지 않는다. 통합 전에는 후속 작업 입력에 이 문서를 명시하며, AGENTS.md가 자동으로 읽게 된 상태라고 주장하지 않는다. STEP 02에서는 AGENTS.md·CLAUDE.md·구현 코드·workflow를 수정하지 않는다.

이미 요청된 범위 안에서 조사·격리 브랜치 작성·최소 수정·자체 검증·복구·문서화·문서 작업 브랜치 전달은 연속 진행한다. 위험도 높음은 **검증 강도**를 정하는 기준이며 자동 승인 대기 사유가 아니다. 이미 받은 승인을 다시 묻지 않는다. 이번 요청의 '중간 승인 없이 안전한 작업 연속 수행'은 기존 AGENTS.md의 일반 시작 승인 절차보다 우선한다.

필수 자료 부재, 실제 대상 버전 불명, 요청 밖 디자인/운영 정책 변경, 해결되지 않은 LOCKED 의도 충돌, 기존 담당자의 공개 후보 교체, 별도 권한이 필요한 배포처럼 스스로 결정할 수 없는 부분만 멈춘다. 가능한 독립 작업은 계속하고 **확인할 사실과 막힌 범위**만 구체적으로 묻는다. UI 정상 여부를 사용자가 대신 검사하도록 넘기기 전에 도구로 검증할 수 있는 부분을 수행한다.

## 2. 수정 전 영향 범위 확인

다음 여섯 항목을 짧게 기록한다. 작은 변경은 작업 메모/PR의 한 단락으로 충분하며 매번 새 보고서를 만들지 않는다.

| 항목 | 최소 기록 |
| --- | --- |
| 목적·경계 | 재현 증상 또는 요청 결과, 바꿀 속성·기능, 범위 밖 항목 |
| 버전 | clean/기존 변경 상태, 작업 브랜치·부모 SHA, 테스트 대상 자산 SHA·공개 URL·생성 CSS |
| 소유자·소비자 | `rg`로 선택자/함수/이벤트/FILES/JS 주입 CSS/미디어 조건 검색. 실제 DOM root·표시/숨김 인스턴스·IX2 포함 |
| 보존 계약 | 정상 화면·콘텐츠·링크·포커스·모션·측정 의미 중 영향받을 수 있는 것 |
| 검증·복구 | 위험도와 이유, 관련 페이지/상태/폭, 실패 시 되돌릴 커밋·자산·head 설정 |
| 불확실성 | 사실/가설/미확인 구분. 현재 로컬 파일을 최신 공개 자산으로 오인하지 않음 |

공통 CSS면 실제 소비자 목록을 확인한다. `global/`에 있어도 page ID로 제한된 규칙은 국소적일 수 있고, `home/` 파일의 `html, body`는 문서 전체에 닿는다. `body *`, 상속, `:has`, wrapper transform, 동적 스타일, inline important를 빠뜨리지 않는다. 공통 로더의 path 중복 방지 때문에 새 SHA가 실제로 선택되지 않을 수 있다.

## 3. 위험도와 최소 검증

해당하는 조건 중 가장 높은 등급을 사용한다. 영향 범위를 설명할 수 없으면 보수적으로 높음으로 분류하고 조사한다. 줄 수·파일명·'리팩터링'이라는 이름으로 낮추지 않는다.

| 위험도 | 분류 예 | 최소 검증 | 매번 요구하지 않는 것 |
| --- | --- | --- | --- |
| 낮음 | 문서·주석, 동작/배치에 영향 없는 확인된 국소 텍스트·속성 | diff/관련 링크·범위 확인. 사용자에게 보이는 변화면 해당 영역과 이웃 캡처·관련 동작 1회. 문구 길이가 줄바꿈을 바꾸면 중간으로 올림 | 문서만 바뀐 작업의 브라우저·JS 전체 테스트, 무관한 전체 페이지 검사 |
| 중간 | 기존 root 내부 간격·크기·상태, 한 컴포넌트 CSS 원문 정리 | 대상과 이웃 전후 캡처/계산값, 관련 상태·기능, 영향받는 PC/태블릿/모바일과 바뀐 경계 ±1px. 관련 기존 테스트와 해당 파일 문법 | 무관한 페이지·모든 미디어 경계·기기 조합 전체. 동작을 바꾸지 않는 사소한 수정의 새 테스트 파일 |
| 높음 | 문서 overflow/transform·전역 글꼴/줄바꿈, 여러 소비자의 공통 속성, 로더/SHA/head, 준비·노출/타이머 소유, viewport meta | 아래 고위험 절차 + 소비자/variant별 전후 시각·핵심 동작. 바뀐 정책을 소비하는 모든 페이지 유형과 예외, 관련 경계/회전/지연·실패 경로. 버그 수정이면 원본 실패→후보 통과의 회귀 검사, 동작 보존 정리면 전후 계약 동등성 | 관련 없는 기능의 전수검사. 전 사이트 선택자 변경일 때만 그 실제 전파 범위까지 넓힘 |

고위험 절차:

1. 격리 DOM/모의 네트워크 등 최소 재현에서 원인과 후보를 검증한다. 동작 보존 정리라면 정상 계약의 전후 동등성을 확인한다. 소스 문자열 검사만으로 CSS 결과를 판정하지 않는다.
2. 실제 기준 HTML·같은 자산 집합을 고정한 시험본에서 대상과 정상 대조 화면을 비교한다. global 정책이면 홈·소개·FAQ·services를 기본 대조로 삼고 내과/영상의학/다른 소비자가 있으면 추가한다. 4페이지 검사만으로 전역 정책을 보증하지 않는다.
3. 공개 staging에서 검증할 때는 후보 자산 SHA와 생성 CSS가 시험 대상과 일치하는지 확인한다. 다르면 '격리 후보 통과, 공개 staging 미검증'으로 남긴다. 후보 고정을 무단 해제해 일치시키지 않는다.
4. 관련 계약 검사·문법·필요한 사용자 흐름을 통과시키고 증거를 남긴다. 실제 배포 후에는 Network/DOM/계산값으로 도달을 확인한다.

검사가 실패·불안정하거나 소비자/동작 불명이 드러나면 그 범위만 확대한다. 성공한 전체 검사를 이유 없이 반복하지 않는다. 이 저장소의 문서 작업에는 문서 diff·링크·범위·커밋/전송 내용 대조가 최소 검증이며, 이번 STEP 02에 적용한다.

## 4. 최소 변경과 정상 동작 보존

- 한 단위에서 원인 하나를 바꾼다. 요청한 문구/간격 수정에 이름 변경·정렬·파일 이동·라이브러리·애니메이션·SEO 정리를 함께 넣지 않는다.
- 기존 파일의 해당 규칙을 수정한다. 같은 선택자를 파일 끝에 다시 선언하거나 JS가 반복해서 스타일을 덮게 만드는 방식으로 수습하지 않는다.
- 현행 `clip`, wrapper transform 방어, fixed header, FAQ `flow-root`, 폰트/critical CSS 게이트, about 상시 노출, 초기화/측정 게이트, 글로우 인계 규칙을 보호한다. LOCKED와 실제 코드가 다르면 실제 실행을 확인하고 모순을 기록한다. 문서 표를 근거로 자동 변경하지 않는다.
- 정상 기준선의 오류까지 보존하는 것은 아니다. 의도한 차이와 보존할 결과를 분리한다. 예: D01의 hidden→clip은 후보의 의도한 차이이며, 가로 넘침 없음·sticky/fixed·모션은 보존할 결과다.
- DOM·콘텐츠·URL·접근성 이름·키보드 순서·포커스 복원·전화/예약/길찾기 맥락을 유지한다. 기기별 복제 요소를 하나로 합치거나 `data-w-id`를 제거하는 변경은 별도 근거 없이 수행하지 않는다.
- 새 CSS/JS 파일은 기본 선택이 아니다. 독립 책임과 로드 필요성이 입증됐을 때만 FILES·workflow 경로·퍼지/워밍업·실제 도달까지 같은 변경 단위로 검증한다. 기존 파일 사용 원칙을 '끝에 계속 덧붙이기'로 해석하지 않는다.
- 호환 규칙을 안 쓰는 것처럼 보여도 공개 고정 자산·레거시 variant·구로더 소비를 먼저 확인한다. 측정 코드를 화면 정리에 편승해 삭제하지 않는다.

## 5. 반응형·시각적 회귀 검증

화면을 바꾸는 모든 작업에는 변경 크기에 맞는 전후 시각 확인이 필요하다. 문서만 변경하면 화면 검증은 생략하고 그 이유를 기록한다.

- 기준 폭 예: PC 1440×900, 태블릿 820×1180, 모바일 390×844. 이는 모든 작업의 필수 3종 세트가 아니라 관련 화면을 고르는 출발점이다. 실제 디바이스·CSS innerWidth·touch·방향도 기록한다.
- 조건 b를 바꾸면 b−1/b/b+1을 확인한다. 767/991 경계라면 각각 766/767/768, 990/991/992다. 479 경계·컴포넌트 고유 경계는 변경이 닿을 때만 추가한다. viewport 교정은 입력 폭과 교정 뒤 innerWidth를 함께 본다.
- 같은 viewport·본문·폰트·자산·네트워크 조건에서 대상과 이웃을 캡처한다. full-page만으로 작은 차이를 놓치지 않도록 필요하면 영역 캡처를 쓴다. 브라우저/OS·후보 SHA·전후 결과를 파일명 또는 결과 기록에 연결한다.
- 정적 상태는 폰트·필수 CSS·레이아웃 준비 뒤 비교한다. 초기 프레임/모션 변경은 준비 전·fade·hold·loop·실패 복구 시점도 확인한다. 애니메이션을 전부 꺼서 숨김/타이밍 회귀를 가리지 않는다.
- 계산값·geometry·scrollWidth와 캡처를 함께 본다. 허용 차이는 요청한 속성에 한하며, 자동 이미지 비교의 허용 오차는 캡처 전에 정한다. 변경 후의 차이를 통과시키려고 오차를 키우지 않는다.
- 메뉴·CTA 등은 열기/닫기, Tab/Enter/Space/Escape 중 관련 키, 포커스 복원, 전화/복사 링크·안내를 확인한다. 예약은 모의 제출, 실전화/예약/외부 메시지 전송은 별도 허용 범위에서만 한다.
- 운영 브라우저 검증 전 측정 요청 차단을 설정하고 실제 차단을 확인한다. URL 표식만 믿지 않는다. 차단이 불확실하면 격리 시험본을 사용한다.
- iOS/iPad viewport·sticky 변경은 해당 엔진/실기기 범위를 확인한다. Chromium의 화면폭 변경만으로 iOS 검증 완료라고 하지 않는다. 필요한 환경이 없으면 가능한 검사와 남은 항목을 구분한다.

## 6. 기존 검사 선택과 실행 조건

기존 검사를 우선 사용한다. **STEP 01의 최신 main에 있던 파일 중 일부는 이 문서 브랜치의 오래된 구현에는 없다.** 대상 코드와 같은 SHA의 검사를 가져오거나 격리 스냅샷을 구성해야 하며, 구버전 검사를 실행해 최신 후보 검증으로 보고하지 않는다.

| 변경 대상 | 우선 검토할 기존 검사 / 보완 |
| --- | --- |
| JS·접근성 소스 계약 | `node scripts/check-site-quality.mjs`, 필요하면 `node --check <변경 JS>`. CSS cascade 보증으로 사용하지 않음 |
| 홈 준비·로더·SHA | `scripts/test-home-loading.mjs`(진단 main), `scripts/test-performance-loader-requests.mjs`, 해당 페이지 bootstrap 검사. 실패/재시도/중복·critical CSS·hero 순서 확인 |
| 공통 메뉴·CTA·위로가기·footer | `scripts/test-shared-ui.cjs`(진단 main)와 대상 variant의 브라우저 비교. 테스트의 실제 URL·자산 override 조건 확인 |
| CTA 폼·포커스 | `scripts/test-floating-cta-focus.mjs`(진단 main), `scripts/test-floating-cta-submit.mjs`. 네트워크 모의 유지 |
| 내과 카드·지역 배치 | `scripts/test-internal-medicine-care.cjs`의 관련 폭/무관한 영역 geometry 검사. 모든 폭을 사소한 다른 컴포넌트 수정에 강제하지 않음 |
| CSS 충돌 D01/D02 | 기존 문법 검사로 대체 불가. 실제 로드 순서의 작은 DOM fixture + 최종 계산값 + 정상 대조 캡처 |

고위험 버그의 새 회귀 검사는 원본에서 실패하고 후보에서 통과하며 사용자 결과를 검사해야 한다. 구현 문자열을 그대로 복제하는 assertion이나 이미 있는 검사 중복은 추가하지 않는다. CI 연결은 필요성이 있는 별도 단위로 설계하고 현재 workflow/branch protection을 실제 확인한다. CI 통과·캐시 purge 성공은 브라우저 도달이나 시각 정상의 증거를 대신하지 않는다.

## 7. 반복 실패와 안전한 복구

같은 증상이 한 번의 원인 기반 후보 뒤에도 남으면 버전·실제 적용·재현 조건부터 확인한다. 두 번째 연속 미해결/재발이 발생하면 덧붙이는 수정을 멈추고 원인을 재진단한다. 검증되지 않은 후보 위에 세 번째 보정을 쌓지 않는다.

1. 실패 화면·조건·SHA·계산값·Network·타이머/observer 로그를 보존한다. 후보가 도달하지 않은 실패와 도달했지만 틀린 실패를 구별한다.
2. 마지막 정상 기준선과 원본/후보를 나란히 비교한다. CSS 명시도·상속·로드 순서, Webflow inline/IX2, 숨은 복제 DOM, 혼재 SHA·초기화 중복을 재확인한다.
3. 아직 미커밋인 자기 변경은 diff를 보존한 뒤 해당 hunk만 제거한다. 관련 없는 사용자 변경에 `reset --hard`, `clean`, 전체 checkout 덮어쓰기를 사용하지 않는다.
4. 공유된 변경은 해당 최소 커밋을 revert한다. 로더/등록/head까지 함께 바꿨다면 같은 복구 단위로 되돌리되, 다른 진행자의 후보 설정을 덮어쓰지 않는다.
5. 배포된 경우 되돌림 커밋 생성만으로 끝내지 않는다. 실제 로드 SHA·계산값·화면/기능이 복원됐는지 확인한다. 권한이 없으면 로컬 복구 상태와 정확한 배포 재개점을 남긴다.
6. 실패 원인·폐기 후보·새 가설·다음 최소 검사를 HANDOFF 또는 해당 작업 기록에 남긴다. 실패한 검사를 지우거나 성공처럼 기록하지 않는다.

## 8. 완료·전달 판정

| 단계 | 완료라고 기록할 수 있는 증거 |
| --- | --- |
| 문서 설계 | 입력 문서/이력 대조, 요구사항·내부 링크·범위·모순 검토, 문서만 담긴 커밋 |
| 구현 후보 | 같은 코드 기준의 관련 검사와 전후 화면/기능 통과. 못 한 필수 검사가 있으면 미완료 |
| staging 확인 | 공개 staging에서 실제 후보 SHA·Webflow 생성 CSS·관련 화면/기능 확인 |
| 정식 반영 | 그 변경의 승인 범위 내 배포 + 실제 정식 자산·화면/기능 확인 |

완료 보고에는 변경 이유·파일·위험도·검증 결과·미검증/차단·커밋/원격 상태·다음 단계를 간결하게 적는다. 단계 하나의 완료를 전체 홈페이지 안정화 완료로 확대하지 않는다. 이번 문서 작업의 push는 문서 작업 브랜치 전달이며 main/staging merge·Webflow Publish를 포함하지 않는다.

Git 통신 차단 시 이미 연결된 인증의 허용된 GitHub API를 사용할 수 있다. 정확한 로컬 commit/tree/blob을 전달하고 반환 SHA·원격 ref·문서 내용·diff 범위를 대조한다. 기존 ref를 force로 덮지 않는다. 원격이 앞서거나 다르면 읽고 병합 여부를 판단하며 전송만 중단한다. API 쓰기도 실패하면 원본 이력을 보존한 patch/bundle과 재개점을 남긴다. 인증값은 출력·문서·커밋에 넣지 않는다.

## 9. AGENTS.md 검토와 후속 통합안

현재 [AGENTS.md](../../AGENTS.md)는 사용자 최신 지시 우선, CLAUDE.md 필수 참조, 요청 범위 고정, 기존 변경 보존, 검증 후 완료를 이미 규정한다. 이를 유지한다. 개선점은 아래 표처럼 좁게 통합하며 **이번 단계에서는 파일을 바꾸지 않는다**.

| 현재 항목 | 통합 제안 | 이유·적용 경계 |
| --- | --- | --- |
| 작업 시작 승인 / 이미 정해진 사항은 재질문 안 함 | 이미 요청된 범위의 조사·수정·자체 검증은 연속 수행한다는 문장 명확화. 필요한 사실/범위 밖 의사결정만 질문 | 현재 두 규칙의 해석 차이를 줄임. 모든 배포의 포괄 승인으로 바꾸지 않음 |
| 범위 고정·기존 구조 우선 | 2절 영향 범위 기록과 4절 원인 하나·원문 정리 원칙을 연결 | 최소 변경의 실제 판단 기준 제공 |
| 기존 기능·반응형 영향 확인 | 3절 위험도 표와 5절 관련 viewport/상태의 최소 검증 링크 | 사소한 변경에 전체 검사를 강제하지 않음 |
| 검증·완료 | 7절 반복 실패/복구, 8절 후보·staging·정식 구분 연결 | 덮어쓰기 누적·미도달 완료 보고 방지 |
| CLAUDE.md 기술 이력 | LOCKED·배포·GA4 예외 원문은 계속 참조. D01/D03 불일치 이슈를 별도 기록 | 낡은 현황을 자동 적용하지 않고 현재 실행 증거와 대조 |
| 모델·추론·사용량 계획 | 해당 요구를 유지하되 승인 대기로 재해석하지 않음. 추천은 실제 선택 가능 범위에서만, 임의 모델 전환·잔여량 수치 추정 금지 | 이번 구조 설계와 무관한 정책 변경 방지 |

후속 지침 통합 단위는 **문서만·낮음 위험**으로 분리한다. 먼저 최신 AGENTS.md/CLAUDE.md 변경 여부를 확인하고, AGENTS.md에는 핵심 원칙과 이 문서 링크만 넣는다. 같은 위험도 표를 두 파일에 복제해 서로 달라지게 만들지 않는다. `이어 붙인다`는 과거 기술 지침의 취지는 기존 로더 경로 사용으로 해석하고, 최종 선언 중복을 쌓는 방식은 금지한다고 명확히 한다. 오래된 main 직행 설명과 현행 staging 우선·GA4 예외도 충돌이 없도록 링크한다.

통합 검증은 우선순위·링크·기존 LOCKED/배포 권한 보존과 네 가지 예제(문서 수정, 한 카드 간격, 전역 overflow, 후보 고정 충돌)의 진행/검증 판단을 검토하는 것으로 충분하다. 구현 코드나 workflow 변경을 섞지 않는다. 통합 요청 전까지 이 계획을 근거로 AGENTS.md를 자동 수정하지 않는다.
