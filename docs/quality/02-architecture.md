## 3. 스타일 계약과 의도한 전파

### 전역과 지역의 구분

1. 전역 규칙은 모든 소비자에게 필요한 문서 정책·기본값에 한한다. 기본값은 가능한 상속과 보통 우선순위를 사용한다. `body * !important` 같은 직접 강제는 기본 설계로 추가하지 않는다.
2. 지역 규칙은 기존 `html[data-wf-page="…"]`, `#hx-di-page`, `.hx-im-*`, `.hx-fcta-*` 등 확인된 root/prefix로 제한한다. 예시를 실제 DOM에 없는 선택자로 추정 적용하지 않는다.
3. 속성의 최종 책임 위치는 한 곳으로 정한다. 같은 속성을 Webflow·공통 CSS·페이지 CSS·JS가 쓰면 상태와 인계 시점까지 표에 적는다. 파일 위치만으로 책임을 판단하지 않는다.
4. 지역 배치 수정이 문서 overflow, body transform, 전역 폰트 굵기, 다른 버튼의 shadow를 바꾸면 범위 누출로 판정한다. 문서 정책 변경은 명시적으로 고위험 단위로 승격한다.

### 공통 규칙의 변경 계약

- 공통 수정 전 **실제 소비 페이지·마크업 변형·고정 자산 SHA** 목록을 만든다. 파일을 로드해도 선택자가 매칭되지 않는 경우와, 구버전 자산을 로드하는 경우를 구별한다.
- 의도한 전파는 같은 컴포넌트·같은 상태·같은 의미의 속성에 한한다. 한 페이지에 다른 섹션이 있다는 이유로 독립 버튼의 모습이 바뀌는 `body:has(...)` 결합을 새로 추가하지 않는다.
- 차이가 필요하면 기존 컴포넌트 root의 상태/variant를 우선한다. 명시적 variant 도입이 필요할 때만 실제 DOM·CSS·초기화 경로를 함께 확인한다. 한 번의 국소 수정에 범용 variant 체계를 만들지 않는다.
- 전역 token 추가도 모든 소비자가 바뀌는 고위험 변경일 수 있다. 값 하나 재사용만을 위해 새 token 체계나 공통 유틸리티 계층을 도입하지 않는다.
- 이미 보호 역할을 하는 `!important`, inline style, 초기화 가드는 유지한다. 새 예외가 꼭 필요하면 원인·소유자·정확한 선택 범위·삭제 조건을 적고 충돌 원문을 함께 정리한다. 파일 끝에 더 강한 선언만 추가하지 않는다.
- CSS 로드 순서는 검증 대상이다. 이번 이행에 `@layer`, CSS Modules, 전체 선택자 개명을 도입하지 않는다. 기존 비계층 CSS와 우선순위가 달라지는 별도 작업이기 때문이다.

## 6. 의존성과 분리 기준

- 불필요한 의존성이란 사용처·호출·초기 상태·호환 대상이 없음을 확인한 연결이다. 이름이 어색하거나 두 로더 목록에 반복된다는 이유는 제거 근거가 아니다.
- `__hxHomeFirstpaintReveal`, `helix-s1-done`, critical CSS 대기, 중복 초기화 가드, path 기반 누락 보완은 현재 필요한 연결로 보존한다.
- 우선 같은 파일 안에서 책임 주석·root 제한·상태별 원문 정리로 경계를 세운다. 함수는 같은 상태 전환의 실제 중복이 있고 입력·출력·실패 경계가 명확할 때만 묶는다.
- 파일 분리는 독립 수명주기·소비자·검증·로딩 순서가 입증되고, 기존 파일 내부 정리로 해결되지 않을 때만 별도 후보로 삼는다. 새 파일+FILES 등록+workflow 경로/퍼지/워밍업+실제 브라우저 도달을 한 단위로 검증한다.
- 이번 계획에는 라이브러리 제거·추가, GSAP/IX2 교체, 공통 manifest/디자인 시스템 신설이 없다. 기존 호환 코드는 소비자가 사라졌다는 증거를 확보한 뒤에만 제거한다.
