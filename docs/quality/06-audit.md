검사 소스 검토: `test`는 `--update-snapshots=none`, corpus 검증 후 외부 전달 없이 재생한다. 신규/누락 응답·해시 손상·미실행 후보를 거절한다. D01/D02의 `test.fail`은 알려진 원본 충돌을 드러내고 예상 밖 통과도 실패시킨다. 정적 캡처는 연속 CSS 모션 위상을 맞추고 finite transition을 종료하므로 초기 프레임/타이밍 증거가 아니다. 푸터 차이가 글자 주변에 있다는 관찰만으로 원인을 글꼴·GPU·GSAP 중 하나로 확정하지 않았다.

STEP04 복원 소스에서는 D01의 expected failure가 **후보 overlay가 없는 고정 원본에만** 적용된다. 후보 대입은 html/body X clip/Y visible과 섹션 CSS 단독 visible을 정방향 검사한다. `network.cjs`는 추가 fixture가 원본 index를 덮지 못하게 하고 본문 해시를 검사한다. `overflow.cjs`는 원래 link 바로 뒤에서 후보를 대입하고 원래 link를 비활성화한 뒤 복구하며, geometry·opacity·transform·문서 높이/scrollY·제목/링크·PNG·fixed/sticky·위로가기 클릭을 확인한다. **같은 문서에서 초기화가 끝난 뒤의 비교**이므로 초기 로드·배경 잠금·리사이즈 재초기화까지 보증하지 않는다.

현재 main의 `site-quality.yml`에는 이 고정 시각 재생이 연결되지 않았다. 문법/측정/폼/포커스 등 기존 CI는 유지되지만 시각 회귀의 자동 차단과 필수 체크 강제 여부는 별개다. 불안정한 비교를 곧바로 필수 CI로 추가하지 않았고, workflow도 수정하지 않았다. 재현 안정화·corpus 영구 복원·동일 환경을 갖춘 뒤 별도 CI 단위로 연결해야 한다.

### 최종 Work 판정의 교차 검토

보고서 텍스트를 보충 ZIP의 `fresh-pixel-results.json`, `wheel-final.json`, `resize-finding.json`, 초기 로드·폰트·기준 무결성 기록과 대조했다. 62조건 후보 비교는 최대61px로 모두100px 이내이고, 원본 반복은480×844 홈 한 조건이221px로 실패했다. 820 새 로드 푸터의 전후0px는 기존 Debian 기준 PNG 불일치의 해결 증거가 아니다.

Work의 실제 휠 입력은 원본·후보 ×3크기 모두 메뉴와 예약창 배경 scrollY를 이동시켰다. PC에서 카드가 표시된 뒤820으로 줄이면 양쪽 버전의 태블릿 카드/SVICC opacity가0으로 남았다. 이번 감사에서도 고정 원본+추가60응답, 후보 정확한 CSS 해시 대입으로 두 문제를 독립 재현했다. 이 두 문제는 U01이 새로 만든 회귀라는 근거가 없지만 기존 기능 정상·폭 전환 보존의 전체 통과를 막는다.

원문 STEP04 보고서에 안내된 `overflow.cjs`와 fixture는 현재 감사 브랜치의 설치된 명령이 아니라 복원 sandbox의 재현 경로다. 원문을 이력으로 보존하며, 현재 브랜치의 실행 가능한 일반 검증 명령은 AGENTS/STEP03 기준선을 사용한다. 복원 소스·추가 입력은 감사 증거 묶음과 원격 Work 보충 ZIP으로 식별한다.

이 Work 환경은 Windows 앱의 Chromium이며 URL을 로컬 고정 서버로 변환하고 SRI·전송 차단을 동일하게 적용했다. 정적 비교에서는 F8로 GSAP/Web Animations/SMIL을 잠시 멈췄고 동작 검사는 재생 상태에서 수행했다. 추가60응답은 기존286 URL과 겹치지 않으며 본문 해시도 검증했다. 원래 URL 그대로 실행하는 Debian 재생·공개 후보 도달·동일 시각의 초기 모션 비교와 구분한다. HTML49MB 원본의 이미지 전체를 이번에 다시 렌더링한 것은 아니며, 확보한 텍스트·원시 JSON·서버 소스와 별도 실행 근거를 검토했다.

## 4. 실제 수정 사례의 효과와 한계

### U01: 문서 overflow 소유권

후보는 `home/global/sections-animations.css`의 문서 전체 선택자를 삭제하고 기존 `global/global.css`가 정책을 소유하도록 한다. ZIP의 patch를 before에 적용한 결과와 candidate의 바이트·blob을 대조했다. before blob `fbb842d905940617e6f9d184fc248296b606e59c`, after `3d38cecdb6722e776a1492c6176bf751d480f361`이다. 새 runtime 파일/로드 등록/전역 보호 수정 없이 사이트 변경을 한 CSS hunk와 주석으로 한정했다.

독립 Chromium fixture에서 390/820/1440px 모두 원본 X hidden/Y auto → 후보 X clip/Y visible을 확인했다. 섹션 CSS만 적용하면 원본은 body X hidden을 만들고 후보는 기본 visible을 보존한다. **섹션이 문서 정책을 덮는 의존 경로가 하나 제거된 효과는 확인**된다.

동시에 문서 정책 변경 자체의 영향은 국소적이라고 보장할 수 없다. 합성 DOM의 body margin8px·첫 section margin11px 조건에서는 section Y가19→11px로 변했다. 이는 실제 홈 회귀 재현이 아니며 사용자 페이지의 오류로 판정하지 않는다. body margin0 대조와 상세 결과는 감사 대장에 분리한다. 선택자 제거의 성공만으로 주변 geometry 보존을 추정해서는 안 된다는 근거다. STEP04의 실제 홈/소개 28조건·112쌍 기록과 독립 로드 실패를 함께 검토해야 한다.

변경 크기는 작아졌으나 검증 범위는 document 정책에 맞게 넓다. 소개는 이 CSS를 소비하지 않는 정상 대조이고, 홈은 직접 소비자다. 수정 독립성의 개선은 확인하지만 운영에서의 회귀 빈도 감소·작업시간 절감은 아직 측정하지 않았다.

검증 효율은 선택 실행 기능에서 확인된다. 이번 태블릿 홈 선택은 전체21개 대신 정상1개·관련 계약1개를17초에 실행했고, 중단된 나머지는 중복 PC 검사를 빼고 이어갈 수 있었다. 이는 작업 선택 기능의 효과이며 전체 검사와 같은 범위의 성능 비교는 아니다. 원자료 분산·bundle 부재·푸터 비교 불안정성은 재현 비용을 늘렸다. 수정 독립성과 도구 기능의 개선을 실제 순개발시간 감소로 환산할 근거는 아직 없다.

### 기존 실제 오류: 푸터 이메일 측정

`9a00676`은 이메일 처리에 섞인 `entry.key` 참조를 이메일 식별값으로 바꾼 4줄 수정이며 CSS·다른 모듈은 바꾸지 않았다. 현재 `test-footer-email-measurement.mjs`를 당시 부모 소스에 실행하자 이벤트0/기대1로 실패했고, 수정 후 소스는 28조건 통과했다. 소스에 특정 문자열이 있다는 검사보다 실제 복사·키보드·SNS·측정 결과를 검증하는 작은 행동 검사가 유용한 사례다. 이 과거 수정은 STEP04의 운영 개선 실적으로 세지 않는다.

## 5. 상시 운영 지침 통합과 재개 조건

AGENTS는 상세 표를 복제하는 대신 [03-rules.md](03-rules.md) 2~8절을 연결했다. 수정 전 영향 기록은 짧은 메모/PR 한 단락으로 충분하다. 낮음은 문서 diff·링크, 중간은 대상/이웃·관련 기기/경계·기능, 높음은 최소 재현·소비자/variant·실패 경로를 검사한다. 실행 명령과 corpus 복원·버전 조건은 AGENTS와 [04-baseline.md](04-baseline.md)에 명시했다.

충돌 정리: 이미 요청된 작업의 재승인을 요구하지 않음; “기존 파일에 이어 붙임”을 끝없는 덮어쓰기로 해석하지 않음; 오래된 main 직행 설명보다 staging 우선/측정 예외 적용; LOCKED 설명과 실제 코드 불일치는 자동 수정하지 않음; 문서/후보/staging/정식 완료를 구분함. 모델·사용량 추천 정책과 기존 사용자 변경 보호는 유지했다.

| 작업 예 | 진행 / 최소 검증 |
| --- | --- |
| 문서 한 줄 수정 | 바로 수정·diff·링크. 전체 브라우저 검사 불필요 |
| 한 카드 간격 | root/소비자 확인, 대상·이웃 전후와 해당 폭/경계·핵심 기능 |
| 문서 overflow | 고위험. 원본 실패→후보 계약, 실제 홈/대조 geometry·스크롤·고정 UI, 독립 로드 시각 재현까지 |
| 다른 담당자의 공개 후보 고정과 충돌 | 고정 유지, 목적/담당/대상 확인. 격리 검증은 계속하며 공개 통과로 표현하지 않음 |

**재개 가능:** 최신 main/staging과 실제 자산을 먼저 확인한 별도 브랜치에서, U01과 독립인 문서·국소 개발을 위험도에 맞게 검증하며 진행. 현재 감사 브랜치 전체를 merge하지 않는다.

**재개 전 필수:** U01 승격/추가 구조 변경 누적 전 푸터·480홈 비교 불안정성의 원인 분리와 독립 로드 전체 무실패 근거, 배경 스크롤 잠금·PC→태블릿 카드 미표시의 별도 수정/회귀 검사 또는 명시적 처리 결정, staging 홈 고정의 목적/담당과 후보 SHA·생성 CSS 도달 확인. 원본 bundle 부재에 따른 전체 Git 이력 동일성 한계도 유지한다. D02/D03/CTA/viewport는 각각 독립 진단과 검증을 갖춘다. 실제 iOS 영향을 바꾸는 작업은 해당 엔진/기기 검증 또는 명시된 미검증 상태가 필요하다.

이번 전달은 감사·지침·근거 보존이다. U01 소스를 현재 작업본에 적용하거나 main/staging에 병합·Publish하지 않는다. 커밋과 원격 전달 상태는 [최종 인계](HANDOFF.md)의 현재 절을 따른다.
